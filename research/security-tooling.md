# Pre-Publication Scanning Pipeline: Verified Research Findings (2026-08-27)

## 1. Prompt-injection / LLM-content scanning tools

- **LLM Guard (Protect AI)** — Python library of 35 input/output scanners (prompt-injection classifier, PII, toxicity). MIT license. **Dead**: Palo Alto Networks closed its Protect AI acquisition 2025-07-22 (folded into Prisma AIRS); last release v0.3.16 May 2025; repo archived read-only 2026-07-09, HF models unmaintained. Embeddable as a pip library, but you'd own a frozen fork. https://github.com/protectai/llm-guard, https://senthex.com/en/llm-guard-alternatives/
- **NVIDIA garak** — offensive red-teaming/vulnerability scanner (probes a live model endpoint; not a content scanner). Apache-2.0, active: v0.15.0 (2026-05-01) added multi-turn GOAT, agent-tool probes, system-prompt-extraction probe. Python library + CLI; runs server-side but designed to attack models, not scan files. https://github.com/NVIDIA/garak
- **Microsoft PyRIT** — red-teaming orchestration framework (attack generation/scoring against a target model), not a static content scanner. MIT, active: v0.11.0 Feb 2026, Python 3.10–3.13, embeddable library. https://github.com/Azure/PyRIT
- **promptfoo** — LLM eval + red-teaming CLI/library (50+ attack plugins incl. an **ascii-smuggling plugin**), MIT. **OpenAI announced acquisition 2026-03-09** (TechCrunch, CNBC, openai.com); OpenAI says the open-source project continues under MIT. Node library/CLI; red-team mode targets a running app. https://openai.com/index/openai-to-acquire-promptfoo/, https://www.promptfoo.dev/docs/red-team/plugins/ascii-smuggling/
- **Rebuff (Protect AI)** — multi-layer injection detector (heuristics + LLM + vector DB + canary tokens). Apache-2.0. **Archived 2025-05-16, unmaintained.** https://github.com/protectai/rebuff
- **Lakera Guard** — commercial runtime guard API (input/output classification: injection, jailbreak, leakage; claims sub-50 ms). **Acquired by Check Point, announced Sept 2025 (~$300M reported)**. SaaS API + enterprise on-prem; not an embeddable OSS library. https://www.checkpoint.com/press-releases/check-point-acquires-lakera-to-deliver-end-to-end-ai-security-for-enterprises/, https://docs.lakera.ai/docs/api/guard
- **HiddenLayer** — commercial platform: model scanning + AIDR runtime detection of injection/jailbreaks; 2026 "Agent Harness Security" for coding agents. Independent (no acquisition found). API/platform, not embeddable OSS. https://hiddenlayer.com/innovation-hub/how-to-secure-agentic-ai
- **Prompt Security** — commercial inline blocking proxy for GenAI apps/browsers. **SentinelOne announced acquisition 2025-08-05 (~$250M)**. SaaS/platform. https://www.sentinelone.com/press/sentinelone-to-acquire-prompt-security-to-advance-genai-security/
- **Notable 2025–2026 arrivals**: **Meta LlamaFirewall** (April/May 2025) — open-source guardrail framework: PromptGuard 2 (86M/22M classifier detecting injections in untrusted content — directly usable on file content), AlignmentCheck, CodeShield (https://arxiv.org/abs/2505.03574). Open guardrail classifier models suited to offline content scoring: **Meta Prompt Guard 2, IBM Granite Guardian, Google ShieldGemma**. **mcp-scan (Invariant Labs) → now snyk/agent-scan** — "security scanner for AI agents, MCP servers and agent skills": static scan of tool descriptions/skill files for tool poisoning, rug pulls, toxic flows + proxy mode; Apache-2.0, actively developed (pushed 2026-08-27); static classification calls Invariant/Snyk's Guardrails API. Closest existing analogue to our registry pipeline. https://github.com/invariantlabs-ai/mcp-scan, https://invariantlabs.ai/blog/introducing-mcp-scan

## 2. Hidden/obfuscated-text attacks in markdown/prompt files

- **Unicode tag-block "ASCII smuggling"** (U+E0000–E007F): invisible in UIs, interpreted by LLMs. Canonical: Johann Rehberger (Embrace The Red) "ASCII Smuggler" (Jan 2024) and Claude-specific demo (2024); "Sneaky Bits" update (2025) covers variation-selector and other encodings. One of the search-result page titles retrieved during this research literally carried a live tag-block payload — these exist in the wild. https://embracethered.com/blog/posts/2024/hiding-and-finding-text-with-unicode-tags/, https://embracethered.com/blog/posts/2025/sneaky-bits-and-ascii-smuggler/. CSA research note covers Unicode instruction injection specifically in AI skill files/MCP tool descriptions: https://labs.cloudsecurityalliance.org/research/csa-research-note-unicode-instruction-injection-ai-skills-20/
- **Bidi controls / Trojan Source** — CVE-2021-42574 (bidi override), CVE-2021-42694 (homoglyphs); Boucher & Anderson, Cambridge, 2021-11-01. https://krebsonsecurity.com/2021/11/trojan-source-bug-threatens-the-security-of-all-code/
- **Zero-width chars** (U+200B/200C/200D, U+FEFF, U+2060): steganographic payloads/watermarks invisible in rendered text.
- **Homoglyphs/confusables**: Unicode **UTS #39** + `confusables.txt` is the canonical mechanism (skeleton algorithm, mixed-script detection). https://www.unicode.org/reports/tr39/
- **HTML-comment / CSS-hidden text in markdown**: `<!-- -->` renders as nothing but reaches the model verbatim; documented against AI review agents (Azure DevOps MCP flaw, July 2026: https://thehackernews.com/2026/07/microsoft-azure-devops-mcp-flaw-lets.html) and in "When Skills Lie: Hidden-Comment Injection in LLM Agents" (arXiv 2602.10498). GitHub strips HTML-comment text before passing issue/PR content to Copilot. CSS `display:none`/white-on-white applies to HTML-bearing markdown; hidden prompts in webpages observed in the wild (Unit 42: https://unit42.paloaltonetworks.com/ai-agent-prompt-injection/).
- **High-entropy base64 in prose**: standard detection is Shannon-entropy + base64-charset rules as in gitleaks (configurable entropy per rule) and trufflehog detectors; garak also probes encoding-bypass acceptance.
- **Detectors/rulesets**: Rust compiler bidi lints (rust PR #90462); ESLint anti-Trojan-Source rules; Mozilla mozlint; GNU binutils `--unicode`; VS Code renders invisible/confusable Unicode by default; Python `confusable-homoglyphs` (UTS39-based), `unicode-confusables`; promptfoo ascii-smuggling plugin; snyk/agent-scan for skill/tool files. No single OSS library covers all classes — a pipeline combines a codepoint-class blocklist (tags, bidi, zero-width, PUA) + UTS39 skeleton checks + comment/CSS extraction + entropy rules.

## 4. Signing / attestation state of the art (non-container artifacts)

- **Sigstore keyless**: Fulcio issues short-lived certs bound to OIDC identity; signature + cert logged in Rekor transparency log; the **Sigstore bundle** format packages signature, cert chain, and inclusion proof for offline verification (https://docs.sigstore.dev/about/bundle/). **KMS-backed keys** (AWS/GCP/Azure/Vault via cosign) remain the pattern for private registries that can't tie identity to public OIDC; private Sigstore deployments are also viable.
- **DSSE + in-toto**: an attestation = in-toto **Statement** (subject digests + predicate) wrapped in a **DSSE envelope**; SLSA provenance is one predicate type. (https://secure-pipelines.com/ci-cd-security/artifact-provenance-attestations-slsa-in-toto/)
- **SLSA**: v1.0 Build levels L1 (provenance exists) → L2 (hosted build, signed provenance) → L3 (isolated build, unforgeable provenance). **v1.1 approved 2025-04-21**; **v1.2 announced Nov 2025** (https://slsa.dev/blog/2025/04/slsa-v1.1, https://slsa.dev/blog/2025/11/announce-slsa-v1.2).
- **npm**: provenance attestations (Sigstore, SLSA provenance) shipping since 2023; **trusted publishing (OIDC) GA 2025-07-31**, provenance on by default with it; GitHub-Actions-built public packages get SLSA Build L3-class attestations (UNVERIFIED exact level claim — sources vary L2/L3). Shai-Hulud npm worm (late 2025) drove adoption. https://github.blog/changelog/2025-07-31-npm-trusted-publishing-with-oidc-is-generally-available/
- **PyPI**: **PEP 740 attestations live since 2024-11-14** (Trail of Bits), default via trusted publishing + gh-action-pypi-publish; verifiable through the Integrity API; ~17% of recently-uploaded files attested per 2026 survey. https://blog.trailofbits.com/2024/11/14/attestations-a-new-generation-of-signatures-on-pypi/, https://docs.pypi.org/api/integrity/
- **crates.io**: **trusted publishing GA July 2025** (RFC 3691); **no signing/attestations shipped** — TUF adoption is open RFC 3724, Sigstore signing (RFC 3403) still proposal-stage. https://blog.rust-lang.org/2025/07/11/crates-io-development-update-2025-07, https://github.com/rust-lang/rfcs/pull/3724
- **TUF**: framework for securing the registry↔client update channel itself (root-of-trust, key rotation, freshness); complements per-artifact Sigstore provenance.

## 6. Pipeline implications

- Don't build on LLM Guard or Rebuff (both archived); for OSS content classification the live options are LlamaFirewall/PromptGuard 2-class models or snyk/agent-scan (Apache-2.0, scans exactly our artifact types).
- garak/PyRIT/promptfoo are red-teaming harnesses, not file scanners — useful for testing our own guardrails, not as the registry gate.
- A deterministic Unicode gate (tag block, bidi, zero-width, PUA, UTS39 confusables) is cheap, high-signal, and has no OSS all-in-one library — build it; strip/flag HTML comments and CSS-hidden spans from markdown before any LLM-based scoring.
- License landmines for an Apache-2.0 product: trufflehog (AGPL) exec-only or replaced by gitleaks (MIT); use **opengrep**, not Semgrep CE rules (Rules License v1.0 forbids competing/SaaS use).
- osv-scanner, syft, grype, sigstore-go are all Apache-2.0 and Go-native — embeddable in-process if the pipeline is Go; sigstore-go (not cosign CLI) is the supported verification library.
- Sign registry artifacts as DSSE-wrapped in-toto statements with SLSA v1.x provenance predicates; support keyless (OIDC) for CI publishers and KMS keys for private publishers — this matches npm/PyPI direction, and crates.io's gap shows verification demand is unmet.
- Verify upstream attestations where they exist (npm provenance, PEP 740 via PyPI Integrity API) for MCP-server dependencies during scan.
- Map findings to OWASP LLM01/LLM03 and ASI04/ASI06 IDs — reviewers and enterprise buyers now expect those taxonomies.
